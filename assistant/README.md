# TodoDay AI 助手（企业微信智能机器人）

在企业微信里对机器人说一句计划，助手把它记进 TodoDay 的任务列表。

```
你：明天下午三点跟老王开会，重要
助手：已记录：
      跟老王开会
      2026-10-16 周五 · 工作 · 高优先级
```

## 用的是哪种接入方式

企业微信里「机器人」有好几种，能力差别很大，选错就白做：

| 方式 | 能收消息吗 | 要公网 HTTPS 吗 | 要加解密吗 |
| --- | --- | --- | --- |
| 群机器人 Webhook | ❌ 只能往外推 | 不需要 | 不需要 |
| 自建应用「接收消息」回调 | ✅ | **需要** | 需要（XML + AES） |
| 智能机器人 · 接收 URL | ✅ | **需要** | 需要（JSON + AES） |
| **智能机器人 · 长连接** | ✅ | **不需要** | **不需要** |

本项目用**智能机器人 + 长连接**（`wss://openws.work.weixin.qq.com`）。由我方主动连出去，所以不需要公网地址、不需要反向代理、消息是明文 JSON。代价是进程必须常驻并保持心跳、断线要自己重连。

## 目录

```
assistant/
  cmd/assistant/main.go        入口：读配置、跑长连接、优雅退出
  internal/config/             配置读取与启动校验
  internal/aibot/              长连接：帧结构、订阅、心跳、重连、回复
  internal/parse/              Kimi 解析 + 规则兜底
  internal/todoclient/         调用 TodoDay 后端的 HTTP 客户端
  internal/bot/                编排：解析 → 建任务 → 回复
  .env.example                 全部配置项示例
```

## 它是怎么工作的

```
企业微信                                   本服务
   │                                          │
   │◄──── wss 长连接（我方主动连出）─────────┤
   │  aibot_subscribe(bot_id, secret) ────────►│  订阅
   │  ◄──── {errcode:0} ─────────────────────  │
   │  ping（每 30 秒） ──────────────────────►│  保活
   │  aibot_msg_callback ────────────────────►│  收到消息
   │       body: msgid / chattype /            │
   │             from.userid / text.content    │
   │       headers.req_id ◄── 回复的唯一凭据    │
   │  ◄──── aibot_respond_msg ────────────────│  解析 → 建任务 → 回执
   │        headers.req_id（原样透传）          │
```

**三条不能踩的线**：

1. **回复必须带 `req_id`**。长连接的回复是「回给某一次回调」，不是「回给某个人」——回调和回复靠 `req_id` 配对，丢了就发不出去。
2. **`req_id` 与 `headers` 是嵌套结构**，不是顶层字段。拼错层级表现为「连上了但机器人不回应」。
3. **同一个机器人只能有一条有效长连接**。新连接订阅成功会踢掉旧的，所以重连必须退避，多实例部署会互相踢。

**幂等**：企业微信在网络异常时会重投同一条消息。`msgid` 直接作为建任务的 `clientId`（前缀 `wx_`），后端对相同 `clientId` 返回既有任务而不新建；进程内另有一份 `msgid` 去重缓存（上限 2000），重投时不会再跑一遍解析、也不会重复回复。

## 配置

### 推荐：在网页「设置」页填

登录 TodoDay 网页版，侧栏「设置」里填机器人 BotID / Secret 与 Kimi 凭证，点保存。凭据由后端加密保存（主密钥 `TODO_CONFIG_KEY`，见后端文档），助手启动时自动取用，**改完配置重连即生效，不用重启进程**。

此时下面的 `WECOM_BOT_ID` / `WECOM_BOT_SECRET` / `KIMI_API_KEY` 都可以留空。

### 兜底：环境变量

复制 `.env.example` 为 `.env` 填写。**本服务不读 `.env` 文件**，只读进程环境变量——用 `export $(grep -v '^#' .env | xargs)` 导入，或写进 systemd / docker 的环境配置。

合并规则（`config.Resolve`）：**后端优先**；后端某字段为空则该字段回落到环境变量；后端整体未配置则全部用环境变量。所以现有的 `.env` 部署不受影响。

| 变量 | 默认 | 机密 | 说明 |
| --- | --- | :---: | --- |
| `ASSISTANT_ADDR` | `:8090` | | 探活端口（`/healthz`）；长连接模式下不是消息入口 |
| `WECOM_BOT_ID` | 空 | | 智能机器人 BotID（**网页设置页可填，这里是兜底**） |
| `WECOM_BOT_SECRET` | 空 | ✅ | 机器人 Secret（同上） |
| `WECOM_BOT_WS_URL` | `wss://openws.work.weixin.qq.com` | | 长连接地址 |
| `TODO_API_BASE` | `http://127.0.0.1:8080` | | TodoDay 后端地址 |
| `TODO_USERNAME` | 必填 | | 用于登录的账号 |
| `TODO_PASSWORD` | 必填 | ✅ | 该账号密码 |
| `TODO_WORKSPACE_ID` | 必填 | | 目标工作区 ID |
| `KIMI_API_KEY` | 空 | ✅ | 留空则全部走规则解析（**网页设置页可填，这里是兜底**） |
| `MOONSHOT_API_KEY` | 空 | ✅ | 同上，别名键 |
| `KIMI_BASE_URL` | `https://api.moonshot.cn/v1` | | Moonshot 的 OpenAI 兼容地址 |
| `ASSISTANT_MODEL` | `moonshot-v1-8k` | | 解析用模型 |
| `PARSE_TIMEOUT` | `8s` | | AI 调用超时 |

必填项缺失时启动即失败，并列出**缺了哪些键名**（不含值）。机器人凭据不再是必填：两边（网页 + 环境变量）都没有时，启动会报错并指向设置页。

启动日志里会打印 `凭据来源：backend` 或 `凭据来源：env`，一眼能看出当前用的是哪一份。

## 企业微信后台配置

1. 管理后台 → **工作台 → 智能机器人 → 新建机器人**。
2. 在机器人配置里切到 **API 模式**。
3. 选择 **长连接** 方式（不要选「接收 URL」——那需要公网 HTTPS）。
4. 从机器人详情页复制 **BotID** 与 **Secret**，填进 `WECOM_BOT_ID` / `WECOM_BOT_SECRET`。
5. **可见范围**里加上要用它的成员，否则他们找不到这个机器人。
6. 启动本服务。

不需要配置回调地址、不需要 Token / EncodingAESKey、不需要可信 IP——这些是「接收 URL」模式才要的。

## 运行

```bash
cd assistant
export $(grep -v '^#' .env | xargs)
go run ./cmd/assistant
```

启动时会先登录 TodoDay 后端并确认账号属于目标工作区，然后才开始连企业微信。配错在启动阶段就报错，不会等第一条消息进来。

### 不开企业微信也能验证配置

`-record-test` 会跳过企业微信，直接把一句话按「解析 → 建任务」跑一遍，然后退出：

```bash
go run ./cmd/assistant -record-test "明天 交周报 #工作 !!!"
```

输出示例：

```
已记录：交周报 ｜ 日期 2026-10-16 ｜ 分组 工作 ｜ 优先级 1（解析来源：rule）
```

这是**配机器人之前**确认凭据、工作区与解析链路是否正常的推荐方式。配置错误会直接报出来，并且指向该改哪个变量：

| 现象 | 含义 |
| --- | --- |
| `没有可用的机器人凭据` | 网页设置页和环境变量都没填 BotID/Secret |
| `凭据来源：env`（但你明明在网页填了） | 助手登录用的账号不是该工作区的 **owner**，取不到明文凭据；或后端没设 `TODO_CONFIG_KEY` |
| `无权访问该工作区：账号不属于工作区 N` | `TODO_WORKSPACE_ID` 填错了 |
| `登录被拒绝：状态码 401` | `TODO_USERNAME` / `TODO_PASSWORD` 填错了 |
| `缺少必填配置：A、B` | 列出所有缺失的键名（不含值） |
| `WECOM_BOT_WS_URL 必须以 wss:// 或 ws:// 开头` | 长连接地址漏了协议 |
| `连接后端失败：…` | `TODO_API_BASE` 不对，或后端没起 |

跑起来之后，日志里应看到「正在连接企业微信长连接」。**要确认真的接通，必须在企业微信里对机器人说一句话**——`aibot_subscribe` 成功只代表连接建立，不代表消息链路通了。

## 测试

```bash
cd assistant
go test ./... -count=1
```

覆盖内容：

- **帧结构**：出站帧的字段名与官方一致（`cmd` / `headers.req_id` / `body.text.content`）；入站消息解析（单聊、群聊、语音转文本、事件回调、订阅回执的 errcode）；命令名常量逐个校验——拼错一个都表现为「连上了但什么都不发生」。
- **回复**：`req_id` 必须透传；缺 `req_id` 时不发送并报错。
- **解析**：表驱动覆盖中英文相对日期、绝对日期、`#分组`、三档优先级、闰年、时区差异、非法日期。
- **编排**：重投去重、空消息、解析失败、记录失败、降级提示、发送失败不影响落库。
- **配置**：必填项、空白值视为未设置、工作区 ID、长连接地址协议校验，以及「旧的自建应用配置项不再被当作必填」。
- **TodoDay 客户端**：401 自动重登并重试、403 与 400 分类、后端不可达。

注意：测试**不覆盖真实的企业微信连接**。协议行为（订阅、心跳、重投）按官方文档实现，但真实的连通性需要你的 BotID/Secret 实测。

## 未实现（如实列出）

- **不包含部署**：没有 Dockerfile、systemd 单元、CI。
- **不做查询/完成/删除/统计**：一条消息就是「记一条任务」。想查今天有什么、标记完成，目前只能开网页。
- **固定单工作区**：所有消息记进配置里那一个工作区，不支持多人各自记自己的。
- **无持久化队列**：回执在内存里排队，进程重启会丢掉未发出的一部分（任务本身已落库，不会丢）。
- **不做多轮对话**：一句话解析不出内容时只提示重说，不会追问。
- **非文本消息**（图片/文件/视频）一律忽略；语音因已转文本，可以记录。
- **不支持多实例**：同一个机器人只能有一条长连接，多开实例会互相踢。要水平扩展得改成单连接 + 共享去重存储。
- **尚未对真实企业微信验证**：仓库里的测试覆盖帧结构与编排逻辑，但订阅、心跳、重投这些需要真实 BotID/Secret 才能确认，必须实测一次。
